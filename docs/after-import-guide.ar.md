# كيف يعمل نظام Awqaf PPM بعد استيراد الخطة الزمنية

**الفئة المستهدفة:** مديرو المشاريع  
**اللغة:** العربية  
**الملفات ذات الصلة:** قالب حزمة المشروع / النموذج الجاهز  
**المنتج:** Awqaf PPM (Strategizeit)

---

## 1. الهدف

حزمة Excel (**Project Pack**) هي الطريقة الرسمية لإنشاء مشروع كامل في النظام دون اتصال:

- **مشروع** واحد
- عدة **تطبيقات** تحت المشروع
- **فريق** العمل (يمكن تعيين نفس الشخص لأكثر من تطبيق)
- **خطة تسليم لكل تطبيق** (مراحل، مهام، معالم، مخاطر)

بعد الاستيراد يدير مدير المشروع التسليم داخل Awqaf PPM (جانت، مهام، معالم، مخاطر، تذاكر) دون الاعتماد على ملف الخطة الزمنية الحر القديم كملف تشغيل يومي.

---

## 2. ماذا تُجهّز في Excel؟

| الورقة | ماذا تملأ | ماذا يصبح في النظام |
|---|---|---|
| Cover / Document Control | هوية الوثيقة والعلامة | للمرجع فقط (لا تُستورد) |
| How_to_Fill | تعليمات التعبئة | للمرجع فقط |
| **01_Project** | صف واحد للمشروع | **المشروع** |
| **02_Apps** | صف لكل تطبيق | **التطبيقات** تحت المشروع |
| **03_Team** | بريد + دور؛ كرّر البريد لعدة تطبيقات | **أعضاء المشروع** + **فرق التطبيقات** |
| **Plan\_\<كود_التطبيق\>** | جدول / معالم / مخاطر لهذا التطبيق | **هيكل العمل (جانت)**، **المعالم**، **المخاطر** |
| 99_Lists | القيم المسموحة | للمرجع فقط |

**قواعد مهمة**

- التواريخ بصيغة `YYYY-MM-DD` فقط  
- الأكواد (`project_code`، `app_code`، `item_code`) لا تتغير بعد أول استيراد  
- البريد الإلكتروني يجب أن يكون مسجلاً مسبقاً في النظام  
- نفس الشخص على عدة تطبيقات = **عدة صفوف** في `03_Team` (نفس البريد + `app_code` مختلف)  
- انسخ `Plan_TEMPLATE` ثم أعد التسمية مثل `Plan_GIS-UNIT` (يجب أن يطابق `app_code`)

## 3. خطوات الاستيراد (من الموقع)

1. سجّل الدخول كـ **مدير مشروع** أو **مسؤول**.
2. افتح **المشاريع (إدارة)**.
3. حمّل **القالب** أو **النموذج** (اختياري)، عبّئه دون اتصال، واحفظ `.xlsx`.
4. اضغط **استيراد الحزمة** واختر الملف.
5. إذا فشل التحقق، صحّح أخطاء الورقة/الصف المعروضة ثم أعد الاستيراد.
6. عند النجاح ينشئ النظام أو يحدّث شجرة المشروع حسب **الأكواد الثابتة** (إعادة الاستيراد آمنة).

يمكن لاحقاً **تصدير الحزمة** من المشروع، التعديل دون اتصال، ثم الاستيراد مرة أخرى.

## 4. ماذا يظهر في النظام بعد استيراد ناجح؟

```text
المشروع (01_Project)
├── التطبيقات (02_Apps)
│   ├── فريق التطبيق (صفوف 03_Team لنفس app_code)
│   └── ورقة الخطة Plan_<كود_التطبيق>
│       ├── الجدول   → جانت / المهام (مراحل ومهام)
│       ├── المعالم  → معالم التسليم
│       └── المخاطر  → المخاطر والمشكلات
└── فريق مستوى المشروع (صفوف 03_Team بدون app_code)
```

### 4.1 المشروع

- يظهر في **الإدارة** وعروض المحفظة  
- المدير والتواريخ والحالة والمرحلة من `01_Project`  
- من **إدارة → المشروع** تعدّل التفاصيل والفريق والتطبيقات

### 4.2 التطبيقات

- كل صف في `02_Apps` يصبح تطبيقاً تحت المشروع  
- يظهر في **إدارة → التطبيقات** و**كتالوج التطبيقات** ومساحة عمل التطبيق  
- المالك / مدير التطبيق من `owner_email` وصفوف الفريق

### 4.3 الفريق (بما في ذلك تعدد التطبيقات)

- أعضاء مستوى المشروع: اترك `app_code` فارغاً  
- أعضاء التطبيق: صف لكل شخص **لكل تطبيق**  
- مثال بعد الاستيراد:
  - مطوّر أ على التطبيق 1 و 2 و 3 → ثلاث عضويات  
  - يرى المطوّر فقط التطبيقات التي انضم إليها (نطاق العضوية)

### 4.4 الجدول → الجانت والمهام ولوحة التطبيق

- كل صف `section=schedule` يصبح عنصراً في **هيكل العمل WBS** (مرحلة أو مهمة)  
- مرتبط بالمشروع وموسوم بالتطبيق من ورقة الخطة  
- **نظرة عامة على مساحة التطبيق:** لوحة تقدم تلقائية (التقدم الإجمالي، أيام التأخير، أشرطة المراحل) من `type=phase` و`weight_pct` وتقدم المهام الفرعية  
- **جانت والجدولة:** اختر المشروع → تظهر أشرطة الخطة المستوردة  
  - حالياً الجانت على **مستوى المشروع** (كل تطبيقات المشروع في مخطط واحد)  
  - المهام تظهر أيضاً في **المهام وإدارة العمل**  
- التقدّم والتواريخ والمسند إليهم والتسلسل (`parent_code`) يبنون شجرة الأشرطة

### 4.5 المعالم

- صفوف `section=milestone` → **معالم التسليم** للمشروع  
- استخدمها لنقاط الاعتماد فقط (UAT، الإطلاق، اعتماد المخطط، …)  
- تواريخ الأساس/التوقع والمخرجات تأتي من ورقة الخطة

### 4.6 المخاطر والمشكلات

- صفوف `section=risk` → سجل **المخاطر والمشكلات** للمشروع  
- تُستورد الخطورة والحالة والمالك وتاريخ الاستحقاق

### 4.7 ما لا تنشئه الحزمة

- التذاكر / محادثة الفريق (تُنشأ لاحقاً داخل التطبيق)  
- سجل رفع المستندات  
- عناصر مسار الاعتمادات  
- معاملات الميزانية  

هذه أدوات العمل اليومي داخل Awqaf PPM بعد وجود الخطة.

## 5. سير عمل مقترح لمدير المشروع بعد الاستيراد

1. **الإدارة** → افتح المشروع → راجع التطبيقات والفرق.  
2. **الجانت** → اختر المشروع → راجع المراحل والمهام والتواريخ.  
3. **المعالم** → أكّد تواريخ الاعتماد مع أصحاب المصلحة.  
4. **المخاطر** → راجع وحدد إجراءات المعالجة.  
5. **التطبيقات / التذاكر** → التعاون اليومي لكل تطبيق.  
6. عند تغيير الخطة دون اتصال → **تصدير الحزمة** → تعديل → **استيراد** مرة أخرى (بدون تغيير الأكواد).

## 6. الصورة الكاملة من البداية للنهاية

```text

        │
        ▼ الاستيراد (إدارة المشاريع)
قاعدة بيانات Awqaf PPM
        │
        ├── مشروع + تطبيقات + فرق
        ├── هيكل العمل → جانت + مهام
        ├── معالم
        └── مخاطر
        │
        ▼ العمل اليومي
تذاكر، محادثات، تحديثات، وإعادة تصدير/استيراد عند الحاجة
```

## 7. أسئلة سريعة

**أين جانت تطبيق واحد؟**  
خطط التطبيقات تُحفظ مع وسم التطبيق، لكن شاشة الجانت حالياً تعرض **المشروع كاملاً**. يمكن لاحقاً إضافة تصفية حسب التطبيق؛ حتى ذلك استخدم أسماء/أكواد العناصر القادمة من كل `Plan_<كود_التطبيق>`.

**هل يمكن الاستيراد مرتين؟**  
نعم. النظام يعمل بـ **تحديث حسب الأكواد**. نفس الأكواد تُحدَّث؛ الأكواد الجديدة تُنشأ.

**من يستطيع الاستيراد؟**  
من لديه صلاحية كتابة المشاريع (مدير مشروع / مسؤول).

**أي بريد يعمل؟**  
الأشخاص المسجلون مسبقاً في Awqaf PPM فقط (من الإدارة / الأشخاص).
